The problem

Your agent is guessing. Make it prove its answers.

LLMs process information statistically, not logically. Ask one to evaluate access policies across hundreds of records and it hallucinates systematically — wrong counts, missed conflicts, fabricated permissions. For rules that matter, "approximately correct" isn't correct.

🎲

No more hallucinated logic

Deduction is delegated to a deterministic engine. The same knowledge base plus the same query always yields the same answer.

🌳

Proof trees, not vibes

Every conclusion comes with a formal derivation chain. Rule IDs surface in proofs, so a decision can be cited: "derived from rule RBAC-0043."

🔍

RAG retrieves. Euclid derives.

Semantic search finds similar documents; rule enforcement needs the exact logical chain. Encode policies once, derive answers forever.

Get started

Up and running in two minutes

Install

pip install euclid-mcp           # MCP server + CLI/REPL — pure Python, works out of the box

# Suggested for best performance (optional): without it, a built-in pure-Python engine takes over.
brew install swi-prolog          # apt install swi-prolog · choco install swi-prolog

Use via MCP — Claude Desktop, OpenCode, Cursor, …

{
  "mcpServers": {
    "euclid-mcp": { "command": "euclid-mcp" }
  }
}

The euclid-mcp executable ships with the pip package — no paths or working directory needed. Running from source instead? Use "command": "python3", "args": ["-m", "euclid_mcp"] with cwd set to the repo.

Or try the interactive REPL — included in the same pip package

$ euclid-cli
Euclid-MCP REPL — type facts and rules in Euclid-IR, then `? query`.

euclid > mortal($x) IF human($x)
euclid > ? mortal($who)

  human(socrates)  [fact]

Architecture

How it works

The LLM never reasons — it only describes. All deduction happens outside the model, which is why a local 8B model can outperform 400B+ cloud models on reasoning tasks.

  • The LLM translates the problem into facts, rules, and a query in Euclid-IR.
  • A persistent SWI-Prolog engine executes the deduction (JSON-lines protocol, no per-call spawn overhead).
  • Solutions come back with variable bindings and full proof trees — or a diagnosis of why the query fails.
  • No SWI-Prolog available? A pure-Python native engine interprets Euclid-IR directly, byte-identical semantics.
The language

Euclid-IR — logic without the Prolog syntax

A declarative intermediate representation designed for both humans and LLMs: variables start with $, implication is IF, conjunction is AND. 

# Facts
parent(tom, bob)
parent(bob, ann)

# Rules (recursion is fine)
ancestor($x, $y) IF parent($x, $y)
ancestor($x, $y) IF parent($x, $z) AND ancestor($z, $y)

# Audit-trail ID on any rule
can_deploy($user) IF
    user($user) AND
    has_role($user, deployer)  # RULE: DEPLOY-POL-1

# Arithmetic & negation
stale($u) IF last_login($u, $d) AND $d > 90
blocked($u) IF NOT active($u)

# Query
? ancestor(tom, $who)

Tooling

Eight tools, one purpose

Not just deduction — a complete lifecycle: validate, reason, explain, diagnose, explore scenarios.

reason

Main deduction — solutions with variable bindings and proof trees.

explain

Natural-language reasoning steps derived deterministically from the proof tree. No LLM involved.

diagnose

Why does a query succeed or fail? Missing facts, missing rules, what would make it true.

what_if

Apply modifications to a KB and compare results before touching production.

check_kb

Validate consistency before reasoning; returns the predicate inventory as an extraction contract.

register_kb

Register a knowledge base once under a kb_id; reference it by name on every call.

unregister_kb

Remove a named KB from the registry.

list_kbs

List registered KBs with metadata: hash, version, fact/rule counts.

Token efficiency

Load the rules once. Query them forever.

Complex business rules don't belong in a prompt. Preload a KB at server startup (EUCLID_KB_PATH) or register it under a kb_id — then each request carries only session-specific facts via delta_knowledge. Small models can reason over large rule sets without ever seeing the whole thing.

Auditable by construction

Every result carries content_hash (sha256 of the exact KB text) and version — pin any answer to the precise knowledge it was computed from.

Stateless & scalable

Instances share nothing: run any number behind a load balancer with zero session affinity. One persistent engine per instance serves many requests cheaply.

Battle-tested backend

SWI-Prolog — 35+ years of continuous development — does the heavy lifting, behind a clean intermediate language.
